# 프론트엔드 구조 안내

프론트엔드는 화면 트리를 기준으로 구성하며, 상위 영역이 하위 영역을 사용하는 단방향 의존성을 따릅니다.

```text
src/
├── app/                  # 라우터, 전역 제공자, 최상위 레이아웃
├── pages/                # 경로와 화면별 디렉터리
│   ├── landing/
│   ├── account-settings/
│   ├── tti-*/
│   ├── matches/
│   ├── decision/
│   ├── attractions/
│   ├── itinerary*/
│   └── my-*/
├── features/             # 사용자 기능과 도메인 단위 화면 요소
│   └── notifications/    # 알림 센터와 읽음 상태 저장
├── widgets/              # 앱 공통 위젯과 전역 내비게이션
├── entities/             # 도메인별 API와 Zustand 상태 저장소
│   └── trip/
│       ├── api/          # 여행 도메인 백엔드 통신
│       └── model/        # 여행 도메인 상태 및 동작
├── shared/
│   ├── api/              # axios 인스턴스와 인증 토큰 갱신 처리
│   ├── lib/              # 특정 프레임워크에 종속되지 않는 도우미 함수
│   └── ui/               # 버튼, 카드, 모달, 배지, 진행 표시줄,
│                         # 프로필 이미지, 토스트와 공통 상태 화면
├── styles/               # 전역 디자인 토큰과 공통 스타일
└── types/                # API 및 도메인 타입 정의
```

## 영역별 의존성 규칙

- `pages`는 `features`, `entities`, `shared` 영역을 조합하여 하나의 화면을 구성합니다.
- `features`는 `entities`와 `shared`를 사용할 수 있지만 `pages`를 가져오면 안 됩니다.
- `shared`는 `app`, `pages`, `features`를 가져오지 않습니다.
- 모든 네트워크 요청은 `shared/api/client.ts`를 거치며, 여행 관련 API 주소와 호출 함수는 `entities/trip/api`에서 관리합니다.
- 서버에서 받은 도메인 데이터는 관련 Zustand 저장소에서 관리합니다.
- 입력값이나 모달 표시 여부처럼 화면에서 잠시 사용하는 값은 해당 컴포넌트 내부에서 관리합니다.

## 백엔드 API 연동 현황

현재 프론트엔드는 백엔드에 구현된 인증, TTI 진단, 매칭, 여행, 관광지, 일정, 안전 정보 API를 사용합니다.
계정 설정 변경은 `PATCH /api/users/me`와 연결되어 있습니다.

아직 백엔드에 알림 API가 없으므로 알림 목록과 읽음 상태는 브라우저 저장소에 보관합니다.
추후 알림 API가 구현되면 내비게이션이나 알림 모달을 수정하지 않고 서비스와 상태 저장소만 서버 방식으로 교체할 수 있습니다.
