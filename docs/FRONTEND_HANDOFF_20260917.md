- 작업 위치: `C:\Project\OddTrip-front`
- 작업 브랜치: `front`
- 반영 대상: `origin/dev`
- 디자인 기준: `0562bbe`
- 범위: React 프론트엔드와 프론트 문서만 변경. 로컬 작업에서 `backend/**`, Alembic, 루트 Python `tests/**`, `.env`는 수정하지 않았다.

## 1. 이번 작업의 제품 방향

- 기존 문서형 설문, 여행 커버·탭, 편집 디자인과 우측 채팅 드로어를 유지했다.
- 홈은 현재 여행을 이어 가는 서비스 허브, 커뮤니티는 여행 경험을 읽고 쓰는 별도 공간으로 역할을 구분했다.
- 여행 계획은 `각자 공동 선호 제출 → AI 일정 생성 → 일정 확인`의 3단계로 단순화했다.
- 별도 합의안 경쟁, 장소 투표, 일정 승인·수정 요청은 현재 흐름에서 제거했다. 일정에 대한 이견은 채팅에서 협의한다.
- 서버가 지원하지 않는 기능은 성공 상태를 만들지 않고 `현재 준비 중인 기능입니다.` 안내를 사용한다.

## 2. 구현한 화면과 흐름

### 홈·공통 레이아웃

- 홈에 진행 중인 여행, 다음 행동, 추천 여행 이야기와 서비스 진입점을 재구성했다.
- 공통 컨테이너의 과도한 좌우 여백을 줄이고 제목·설명·버튼, 카드, 로딩·빈 결과·오류 상태의 시각 규칙을 정리했다.
- 홈 배너와 커뮤니티 배너의 목적과 정보 밀도를 분리했다.
- 여행 설정 버튼의 대비와 아이콘을 강화했고, 큰 상태 바는 작은 단계 안내로 축소했다.

### 여행 조율·일정

- `/trips/:tripId/overview`, `/trips/:tripId/coordination`, `/trips/:tripId/schedule`에서 동일한 3단계 진행 안내를 사용한다.
- 각 사용자가 공동 선호를 제출하면 양쪽 제출 상태를 확인하고 AI 일정 생성으로 이어진다.
- AI 제안은 별도 확정안이 아니라 두 답안을 반영해 장소와 일정을 만드는 입력으로 처리한다.
- `/trip/places`는 현재 여행의 `/trips/:tripId/schedule`로 이동한다. 구형 decision, proposal, approval, itinerary 화면은 현재 여행의 새 경로로 리디렉션한다.
- 일정은 읽기 전용이다. `항목 자세히 보기`만 제공하고 승인·수정 요청 버튼은 제공하지 않는다.
- `/my`의 여행 카드에서 해당 여행 정보를 채운 커뮤니티 글쓰기로 바로 이동할 수 있다.

### 일정 지도

- `/trips/:tripId/schedule/map`에 Google Maps JavaScript API 지도를 연결했다.
- 일정 항목 중 `placeId` 또는 좌표가 있는 모든 항목을 유형과 관계없이 수집한다. 관광지뿐 아니라 실제 장소가 있는 식사·숙박 항목도 포함한다.
- 번호 마커, 방문 순서 목록과 산호색 연결선을 같은 순서로 표시한다.
- 연결선은 실제 도로 경로가 아니라 방문 순서임을 화면에 명시했다.
- 마커 상세는 클릭할 때만 연다. 장소·좌표가 없는 이동·대기·일반 슬롯은 일정에는 남지만 지도에서는 제외한다.

### 커뮤니티

- `/community`, `/community/:postId`, `/community/write`, `/community/:postId/edit`, `/community/drafts`를 추가했다.
- 목록 검색, 카테고리, 정렬, 페이지 이동, 상세, 댓글, 공감, 저장, 작성·수정·삭제, 임시저장, 이미지 한 장을 지원한다.
- 상단은 한 번에 베스트 스토리 하나를 소개하는 전체 폭 배너로 정리하고 My Travel Note는 본문 아래 단계로 내렸다.
- 현재 게시판 백엔드가 없으므로 계정별 브라우저 저장소 어댑터만 사용한다. 첫 진입과 작성 완료 시 이 범위를 팝업으로 알리며 상시 DEMO 배지는 표시하지 않는다.
- 자세한 범위와 필요한 서버 계약은 `docs/COMMUNITY_FRONTEND.md`에 정리했다.

### 신고·개인정보 관리

- 사용자·프로필 신고를 `POST /api/users/{userId}/reports`에 연결했다.
- 채팅 메시지 신고는 신고 사유와 확인 절차를 포함해 복원했다.
- `/settings`와 `/settings/privacy`에서 프로필, 동의 기록, 마케팅 철회, 차단 사용자, 회원 탈퇴를 제공한다.
- 비밀번호 변경·재설정은 프론트와 서버 계약이 연결됐다. 이메일 변경은 아직 준비 중 안내만 제공한다.

### 인증·알림·채팅

- 가입 필수·선택 동의를 가입 요청 payload로 보내며 동의 localStorage 저장을 제거했다.
- 매칭 프로필·안전수칙 동의 게이트, 동의 조회·이력과 마케팅 철회를 연결했다.
- 알림 목록, 안 읽음 수, 개별·전체 읽음 처리와 `notification.created` WebSocket 이벤트를 연결했다.
- 401 발생 시 refresh를 공유해 한 번 재시도하고 실패하면 세션을 지운 뒤 로그인으로 이동한다.
- `/chat`은 방 목록, `/chat/:roomId`는 직접 접근해도 우측 드로어로 열린다.

### 관리자

- 운영자 계정은 일반 회원 화면 대신 `/admin`으로 이동한다.
- 대시보드, 회원, 여행, 여행 상세, 신고 검토, 제재 부과·해제를 실제 관리자 API에 연결했다.
- `/admin/attractions`, `/admin/tti`, `/admin/operations`는 일부 정적·조회 전용 범위를 유지하며 진입 시 세션당 한 번 예시 데이터 범위를 알린다.
- 프론트는 `role === "admin"`만 검사하며 권한을 생성하거나 변경하지 않는다.

## 4. 실제 API 연결과 로컬 전용 범위

### 실제 서버에 연결됨

- 인증, 가입 동의, refresh, logout, 회원 탈퇴
- TTI 질문·계산·결과
- 매칭 후보와 요청 생성·수락·거절·취소
- 채팅방·메시지·읽음·메시지 신고·차단과 WebSocket
- 제품 알림 목록·안 읽음 수·읽음 처리
- 여행 CRUD, 공동 선호 제출·상대 상태, AI 에이전트·관광지·일정 생성과 조회
- 사용자·프로필 신고
- 관리자 통계·회원·여행·신고·제재

### 로컬 또는 안내만 제공

- 커뮤니티 글·댓글·공감·저장·초안은 계정별 브라우저 저장소에만 저장된다.
- 관리자 관광지 편집, TTI 편집·버전 배포, 운영 상태는 정적 또는 조회 전용이다.
- SMS 본인확인, 이메일 변경, Push는 준비 중이다. 비밀번호 변경·재설정과 D-1 리마인더는 구현됐다.
- 실제 도로 길찾기, 구간별 이동시간과 응답 출처 표시는 아직 없다.

## 5. 환경 설정

프론트 실행에 사용하는 변수 이름만 기록한다. 실제 키 값은 저장소와 인수인계 문서에 넣지 않는다.

```dotenv
VITE_API_BASE_URL=http://localhost:8000
VITE_GOOGLE_MAPS_API_KEY=
```

- 지도 키에는 Maps JavaScript API와 결제가 활성화되어야 하며 실제 프론트 도메인을 HTTP referrer로 제한한다.
- 백엔드가 좌표 검색·이동시간 계산에 쓰는 키는 프론트 키와 분리하고 서버 IP 제한을 사용한다.
- 키가 없거나 지도가 실패해도 우측 방문 순서와 일정 데이터는 읽을 수 있어야 한다.

## 7. 검증 결과

- `npm test -- --run`: 15개 파일, 61개 테스트 통과
- `npm run build`: 통과. 약 526 kB JavaScript chunk 크기 경고는 남아 있다.
- `git diff --check`: 오류 없음. Windows의 LF→CRLF 경고만 확인했다.
- 지도 스모크 테스트: 테스트 일정 18개 행 중 실제 장소 정보가 있는 8개 항목을 마커와 순서 목록에 표시했고 좌표 누락은 0개였다.
- `/trips/:tripId/schedule/map`: 기존 지도 레이아웃을 유지하고 여행 ID 기반 복구 경계를 추가했다.
- 커뮤니티, 여행 개요, 내 여행, 설정 화면은 브라우저에서 주요 상태와 레이아웃을 확인했다.

## 8. 후속 우선순위

### P0

- 커뮤니티 게시글·초안·댓글·공감·저장·신고 서버 API와 운영자 검토를 추가한다.
- 매칭에 실제 성인·본인인증 상태와 나이대를 연결한다.

### P1

- 일정 항목 수정·삭제·순서 변경과 revision 충돌 처리를 설계한다.
- 실제 도로 경로·구간 이동시간을 연결하고 Google·fallback·AI 결과의 `source`를 응답에 포함한다.
- 장소·일정 변경 WebSocket 이벤트와 오프라인 영구 알림을 추가한다.
- SMS, 비밀번호·이메일 변경, Push, D-1 리마인더를 구현한다.
- 안전정보에 출처·갱신 시각·만료 정책을 추가한다.

### P2

- 관리자 관광지·TTI·운영 상태를 실제 API로 교체한다.
- 모바일·Capacitor 안전영역과 실기기 접근성을 완성한다.
- 큰 JavaScript chunk를 라우트 단위로 분리하고 배포·CI·법적 페이지를 확정한다.

세부 백엔드 차이는 `docs/FRONTEND_BACKEND_INCOMPLETE_CONNECTIONS.md`, 프론트 후속 작업은 `docs/FRONTEND_REDESIGN_TODO.md`를 함께 확인한다.
