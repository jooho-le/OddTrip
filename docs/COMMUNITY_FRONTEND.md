# 여행 커뮤니티 프론트 구현

작업 브랜치: `front` · 디자인 기준: 기존 `0562bbe` 기반 OddTrip UI

## 참고와 디자인

- [네이버 블로그 홈](https://section.blog.naver.com/): 실제 브라우저에서 주제별 탐색, 작성자·제목·요약·썸네일 목록, 공감·댓글, 사이드바 구조 확인.
- [네이버 블로그 글쓰기 안내](https://help.naver.com/service/5593/contents/764?lang=ko&osType=MOBILE): 카테고리, 댓글 허용 등 작성 흐름 참고.
- OddTrip의 주황 포인트, 흰 문서형 화면, 얇은 구분선, 기존 헤더와 글꼴 유지. 네이버의 글·이미지·브랜드 자산은 복사하지 않음.
- 예시 글은 화면 검토용으로 작성했으며 사진은 기존 디자인에서 사용하는 Unsplash 분위기 이미지. 실제 작성자·여행 실적을 나타내지 않음.
- `/home`의 기존 매칭 후보·일정 일치 피드는 커뮤니티 추천·최신·현재 여행지 이야기로 교체했다. 매칭은 `/matches`, 내 여행은 `/my`에서 각각 이어간다.

## 화면

| 경로 | 구현 내용 |
| --- | --- |
| `/community` | 여행기·여행 팁·질문·동행 후기, 검색, 최신순·공감순, 페이지 이동, 내 글·저장한 글 |
| `/community/:postId` | 작성자·지역·날짜, 사진·본문·태그, 공감·저장, 댓글 작성·삭제, 내 글 수정·삭제 |
| `/community/write` | 제목·카테고리·지역·본문·태그, 대표 사진 1장, 사진 설명, 댓글 허용, 미리보기·임시저장·작성 완료 |
| `/community/:postId/edit` | 본인이 쓴 글 수정, 수정 중 임시저장, 기존 공감·댓글 유지 |
| `/community/drafts` | 새 글·수정 초안 목록, 이어 쓰기, 초안 삭제 |

기존 일반 사용자 인증과 관리자 전용 라우팅을 유지한다. 데스크톱 헤더와 모바일 하단 메뉴에서 접근한다.

## 동작 범위

- 서버 게시판 API가 없는 프론트 체험 기능이다. 진입 시 계정별·세션당 한 번 안내 팝업을 표시한다. 상시 DEMO 배지는 사용하지 않는다.
- 글·댓글·공감·저장·초안은 `oddtrip.community.v1.<userId>`에 저장한다. 계정 간 UI 데이터가 섞이지 않으며 새로고침 후 복원된다. 브라우저 저장은 보안 저장소가 아니며 다른 기기·회원에게 동기화하지 않는다.
- 작성 완료 전 확인창과 완료 토스트에도 브라우저 저장임을 명시한다. 서버 게시·공유·신고·제품 알림 전송을 위조하지 않는다.
- 같은 계정의 다른 탭 변경은 storage 이벤트로 읽어 온다. 다중 사용자의 실시간 협업 기능이 아니다.
- 사진은 JPG·PNG·WebP, 800KB 이하 1장만 로컬 첨부한다. 서버 파일 업로드는 없다.
- 저장 공간 부족 시 기존 저장 자료를 유지하고 오류를 안내한다. 손상된 자료를 임의 초기화하거나 덮어쓰지 않는다.
- 글은 일반 텍스트로 렌더링하며 HTML을 실행하지 않는다. 신규 초안은 계정당 한 개, 수정 초안은 글별 한 개다.
- 작성 중 돌아가기·링크 이동·새로고침/닫기에는 유실 안내가 있다. 브라우저 자체 뒤로 가기를 포함해 확실히 보관하려면 임시저장을 사용한다.

## 백엔드 연결 대기

아래는 필요한 계약 범위이며 확정 API 명세가 아니다.

| 우선순위 | 기능 | 필요한 계약 |
| --- | --- | --- |
| P0 | 실제 게시글·초안 | 목록·검색·카테고리·정렬·페이지네이션·상세·작성·수정·삭제, 작성자 인가, 게시 상태·수정 버전 |
| P0 | 공개 범위·관리 | 공개/비공개 정책, 차단 사용자 제외, 삭제·숨김 처리, 게시글·댓글 신고·운영자 검토 |
| P1 | 사진 | 업로드·스토리지·파일 제한·검사·삭제·출처/설명 |
| P1 | 댓글 | 목록·작성·수정·삭제, 댓글 허용 정책·작성자 인가 |
| P1 | 공감·저장 | 계정별 추가·취소, 중복 방지, 개수·내 상태 조회 |
| P1 | 공유·알림 | 실제 공개 글 URL, 권한 없는 글 접근 처리, 댓글 알림과 수신 설정 |
| P2 | 확장 | 이웃/구독, 대댓글, 다중 사진·본문 블록 편집기 |

연결 시 `features/community/communityModel.ts`의 로컬 어댑터를 실제 API 어댑터로 교체하고 예시 자료를 운영 DB에 자동 업로드하지 않는다.

## 검증

- 프론트 단위 테스트: 계정 분리, 초안 복원, 작성·수정·삭제, 필터, 공감 취소, 작성자 제한, 손상 자료 보존, 용량 초과 시 초안 보존, 수정 시 최신 댓글·공감 보존.
- 브라우저 스모크: 인증·기존 알림/채팅 HTTP 응답을 테스트 환경에서 대체하여 커뮤니티 UI를 검증. 실제 백엔드 통합 테스트는 아님. 테스트 중 기존 채팅 WebSocket 연결은 백엔드 미실행으로 연결 거부됨.
- 목록·상세·작성: 1440·1280·1024·390px 수평 오버플로 0. 목록 헤더는 추가로 720·768px 검증.
- 검색·카테고리·페이지 이동, 공감·저장·댓글 후 새로고침, 사진 첨부·초안 복원, 초안 목록, 미리보기·작성·수정·삭제, 없는 글과 신고 준비 중 안내 확인.
- 별도 화면 검토에서 모바일 활성 메뉴 색상·제목 단어 줄바꿈을 보완하고 재검토.
- 백엔드·루트 Python 테스트·환경파일 수정 없음. 기존 미추적 비교 문서는 그대로 보존.
