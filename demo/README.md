# 🧪 일정 생성기 데모 환경

OddTrip backend 없이 **알고리즘만 단독 실행**해서 검증할 수 있는 환경입니다.

## 한 줄 요약

> `python demo/run_demo.py` 한 줄로 일정 생성 결과를 콘솔에서 바로 확인.

## 설치 (최초 1회)

```bash
# 프로젝트 루트에서 실행
cd oddtrip-itinerary-feature

# Python 의존성 설치
pip install -r demo/requirements.txt
```

## 환경변수 설정

```bash
# 예시 파일을 .env로 복사
cp demo/.env.example demo/.env

# .env 열어서 OPENAI_API_KEY 채우기
# (다른 키는 비워두면 mock 모드로 동작)
```

⚠️ **`.env` 파일은 절대 git/슬랙/이메일로 공유하지 마세요.** 실제 키가 들어있어서 노출되면 위험합니다.

## 실행

```bash
# 기본 (서울 3일)
python demo/run_demo.py

# 다른 시나리오
python demo/run_demo.py busan      # 부산 2일
python demo/run_demo.py jeju       # 제주 3일
```

## 검증 체크리스트

데모 결과를 보면서 다음을 체크해보세요:

- [ ] 시간 흐름이 자연스러운가? (이동 → 도착 → 체류 → 다음 이동)
- [ ] 영업시간 안에 방문이 배치되었는가? (특히 박물관 월요일 휴관)
- [ ] 점심(12-14시), 저녁(18-20시) 슬롯이 들어갔는가?
- [ ] 이동 시간이 합리적인가? (도심은 보통 5~30분)
- [ ] 일자별 장소 수가 균등한가? (한 날만 7개, 다른 날 0개 X)
- [ ] aiReason이 자연스러운 한국어인가? (OpenAI 키 있을 때)
- [ ] `python demo/run_demo.py`를 두 번 돌렸을 때 같은 결과? (mock 모드 결정론적)

## 문제 해결

**Q. `ModuleNotFoundError: No module named 'src'`**
→ 프로젝트 루트(`oddtrip-itinerary-feature/`)에서 실행하세요. 데모 스크립트가 자동으로 `sys.path`를 조정합니다.

**Q. `openai.AuthenticationError`**
→ `demo/.env`의 `OPENAI_API_KEY`가 올바른지 확인하세요. 비워두면 템플릿 fallback으로 동작합니다.

**Q. 결과가 비어있음**
→ `sample_data.py`의 InputPlace 리스트가 비어있지 않은지, 날짜 범위가 유효한지 확인하세요.

**Q. 같은 날에 휴무인 박물관이 들어감**
→ `DayAssigner._pick_best_date()`가 휴무를 피하려고 시도하지만, 모든 후보일이 휴무면 우선 배치 후 `time_scheduler`에서 "대체 추천" 슬롯으로 표시됩니다. 의도된 동작입니다.
